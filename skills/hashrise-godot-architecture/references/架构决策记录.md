# 架构决策记录（ADR 摘要）

> Hashrise 的三条不可轻易推翻的决策。写新代码前先确认没有违反这三条。

---

## ADR-001 · 数值以 Resource 资源化，而非硬编码

**状态**：Accepted（Phase 3 锁定）

**决策**：所有可调数值以 Godot `Resource` 子类型承载，存放于 `res://data/`，由 `Config` 单例在启动时加载为内存查表。逻辑代码只通过 `Config` 读取，禁止在玩法逻辑中写死具体数值。

**理由**：
- 平衡迭代高频，散落的硬编码会"改一处漏一处"
- 数值与设计文档会脱钩，"代码真值"脱离设计
- 改数值要改代码重建，策划无法自助
- 逻辑与常量耦合，单元测试要 mock 一堆常量

**后果**：
- 调平衡 = 改 `.tres`，不重建，AI/策划可自助
- 多一层 Resource 加载样板（可忽略的开销）
- 需要维护 `Config` 的查表接口

**替代方案与否决理由**：
- 常量脚本 `Constants.gd`：仍是代码内数值，无法可视化调
- JSON/CSV：失去 Godot 类型安全与 `.tres` 引用
- 远程配置：MVP 阶段严重过度工程

## ADR-002 · 离线收益用 unix 时间差 + 种子化 RNG 复现行情游走

**状态**：Accepted（Phase 3 锁定）

**决策**：

**时钟**：以 `OS.get_unix_time()` 为权威墙钟。
- 存档时写 `timestamp`
- 读档时 `away_sec = clamp(now − saved.timestamp, 0, HARD_CAP)`
- `HARD_CAP` 24 小时硬上限，防改本地时钟刷收益
- 切后台即触发存档，保证时间戳贴近真实离开时刻

**随机**：种子化 `RandomNumberGenerator` 全局唯一。
- seed 在**新档时随机生成并存入存档**（`rng_seed`）
- 每次启动从存档续接 seed → 同一存档的随机序列跨会话连续
- 用于两处：① 在线行情游走 ② 离线风险事件抽样
- 离线收益**主体**用冻结的存档行情价计算，**不**依赖 RNG；RNG 只服务事件损失抽样

**离线对账流程**：

```
away_sec   = clamp(now − saved.timestamp, 0, 86400)
base       = saved_net_rate × eff × min(away_sec, cap)   # 价格冻结
event_loss = RNG.sample_offline_events(away_sec)         # 种子化抽样
event_loss = min(event_loss, 0.4 × base)                 # 封顶 40%
```

**替代方案与否决理由**：
- Timer/帧累计时间差：切后台会丢失或膨胀
- 服务端校时：防作弊最彻底，但 MVP 无后端，post-MVP 再做
- 离线行情实时游走：存档膨胀、回放复杂、玩家离线血亏

**红线**：离线收益**永远非负**；事件损失**封顶基础产出的 40%**；离线期间**行情冻结于存档**（避免"睡一觉血亏"）。

## ADR-003 · 变现藏在 AdProvider / IAPProvider 接口后

**状态**：Accepted（Phase 3 锁定）

**决策**：广告与内购的实现细节全部封装在 `AdProvider` / `IAPProvider` 接口之后。玩法代码只调用 `Monetization.request_ad(reward)` / `Monetization.apply_remove_ads()`。每个平台一份实现，外加一份 Stub（编辑器/桌面下空实现）。

**理由**：
- 玩法逻辑不被 SDK 变更污染
- 没有 SDK 也能跑（编辑器、单元测试、CI）
- 未来换聚合 SDK / 加平台只改实现，不动玩法

**红线**：变现**只加速、不锁内容**（no P2W）。详见 `hashrise-monetization-guard`。

## ADR-004 · 设计文档是数值的唯一权威源

**状态**：Accepted（Phase 3 锁定）

**决策**：数值改动流程固定为**先回写设计文档 → 再改 `.tres`**。代码里不出现具体数值。

**理由**：这是 ADR-001 的延伸。数值一分散，"设计文档"就退化成历史记录，评审失去依据。

**后果**：改一个数字要动两个地方，慢；但换来的"设计与实现永远对得上"，在平衡迭代中价值远大于那点开销。
