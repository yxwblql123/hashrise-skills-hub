# 三层架构落地检查清单

> 搭骨架或做架构评审时逐项核对。每项都能用"看代码 / 跑一次"验证。

## A. 目录与注册

- [ ] `project.godot` 的 `[autoload]` 注册顺序：EventBus → RNG → Config → GameState → SaveManager → AuthManager → Simulation → Monetization → AudioManager
- [ ] `core/` 只放单例与全局系统；`core/data/` 只放 Resource 定义；`core/ads/`、`core/iap/` 只放抽象接口与平台实现
- [ ] `scenes/` 下每个 `.tscn` 有同名 `.gd`；场景不直接引用 `core/` 内部私有方法
- [ ] `design/`（或你的设计文档目录）在仓库里，且是数值的唯一权威源
- [ ] `docs/architecture/adr/` 存放不可轻易推翻的决策记录

## B. 数据与状态分离

- [ ] 全仓库搜索硬编码数值（`= 120`、`* 1.15`、`30.0`），玩法逻辑里应为 0 命中
- [ ] `Config` 提供 `get_miner` / `get_currency` / `get_upgrade` 三类查表
- [ ] 逻辑层没有直接 `load("res://data/...")` 的调用
- [ ] `GameState` 只存运行时态（余额、数量、当前价），不存静态配置
- [ ] `.tres` 里的数值与设计文档逐个对得上
- [ ] 改了数值 → 先回写设计文档 → 再改 `.tres` → 再跑数值测试

## C. 模拟与表现分离

- [ ] 模拟层文件里没有 `get_node("/root/...")` 指向 UI 节点的调用
- [ ] UI 脚本里没有对 `Simulation` 内部方法的调用（只读 `GameState`）
- [ ] 模拟推进用 `Timer`，不是 `_process` 里累加时间
- [ ] 值未变化时**不发**事件信号
- [ ] 事件信号带**最小必要数据**，不传整个 `GameState`

## D. EventBus 纪律

- [ ] EventBus 只有跨层广播事件，没有"内部调用"性质的方法
- [ ] 信号名是状态/事实（`currency_changed`），不是命令（`update_currency`）
- [ ] 每个信号都有明确的生产者与消费者，且消费者都能在 UI 或模拟层指出
- [ ] 没有出现"万能总线"：单个信号被 5 个以上无关模块订阅 → 拆信号

## E. 存档

- [ ] `SaveManager` 是唯一写盘入口，其他人不直接 `FileAccess` 写存档
- [ ] 存档里带 `timestamp`（`OS.get_unix_time()`），用于离线结算
- [ ] 存档带 `rng_seed`，跨会话续接，保证同一存档的随机序列连续
- [ ] 有存档版本号，且有迁移函数（老档能读）
- [ ] 切后台（`NOTIFICATION_WM_GOING_INTO_BACKGROUND`）触发存档

## F. 变现接口

- [ ] `Monetization` 只暴露 `request_ad(reward)` / `apply_remove_ads()` 这类抽象方法
- [ ] 玩法代码不直接引用任何广告 SDK 类型
- [ ] 有 Stub 实现（桌面/编辑器下空实现），保证无 SDK 也能跑
- [ ] 每次广告/内购都有回调路径，即使玩家中途切后台也不会卡住流程

## G. 性能与适配

- [ ] 渲染器选择与目标平台匹配（低端安卓 → GL Compatibility）
- [ ] 视口尺寸与目标设备匹配，UI 用锚点 + 容器，验证多分辨率不溢出
- [ ] 纹理已打包进图集，运行时无重复 `load`
- [ ] 频繁创建/销毁的节点（飘字、粒子）用对象池
- [ ] 屏内可交互元素 ≤ 6 类
