# Steam 商店页撰写与审查

商店页是**唯一的转化入口**：玩家在决定要不要买之前，只会看到这一页。本技能给出 Hashrise 沉淀下来的写法与审查标准。

## 一、先做竞品调研，再动笔

**不要凭想象写文案。** 写之前先做三件事：

1. **找 5 个最接近的同类游戏**，记录它们的：定价、评价数与好评率、当前在线、标签组合、首发折扣、上架距今多久。
2. **拆它们的商店页结构**——它们的短描述怎么开头、About 分几段、第一个 bullet 讲什么、截图顺序怎么排。
3. **读它们的评价**，重点是最有帮助的**差评**。玩家反复抱怨的点，就是你不该在文案里承诺的东西。

Hashrise 的做法：写文案前先读同类游戏的商店页和自己的评价，把"玩家真正在乎的"提炼成 bullet 顺序。

## 二、短描述（Short Description）

Steam 短描述有**长度上限**，且在搜索结果与愿望单卡片里都会显示，所以它是"一句话钩子"，不是简介。

写法要点：

- **第一句必须是具体玩法，不是形容词**。
  - ❌ "一个令人上瘾的放置游戏"
  - ✅ "管理你的矿场：买矿机、交电费、扛住断电，在离线时也在挖矿"
- 带上**差异化的动词**（挖 / 升级 / 交电费 / 扛住），让玩家立刻知道要做什么。
- 结尾给一个**明确的承诺**（玩家能拿到什么），不要留悬念。
- 一句话说完，**不要换行堆砌**。

## 三、About This Game

结构固定为四块，每块解决一个玩家的问题：

| 块 | 回答玩家的问题 | 写什么 |
|----|--------------|--------|
| ① 开场 | 这是什么游戏？ | 2–3 句：类型 + 核心动作 + 差异点 |
| ② 核心玩法 | 我具体玩什么？ | 3–6 条 bullet，每条一个动词开头 |
| ③ 特性 | 为什么值得现在买？ | 系统特色、离线收益、成长曲线、叙事 |
| ④ 合规与说明 | 有什么需要注意的？ | 年龄分级、虚构题材、联网需求、语言支持 |

**bullet 写法**：一条只讲一件事，动词开头，能被截图佐证。

```
✅ 每台矿机都有真实功耗，电费是永动的开销
✅ 三种虚构币种行情各自随机游走，也可能暴跌
✅ 离线也在挖矿，回来能领收益——但机器可能过热
```

不要写成营销腔的形容词堆砌。玩家买的是**能玩到的东西**，不是形容词。

## 四、标签（Tags）

标签直接决定你出现在谁的推荐位上。规则：

1. **前 4 个标签是最重要的**，Steam 按顺序展示并据此匹配。
2. **先选类型标签**（Idle / Simulation / Management），再选机制标签（Economy / Incremental），最后才是题材标签（Crypto / Mining）。
3. **题材标签要慎用**。Hashrise 用"加密矿场"题材，但为规避真实金融联想，视觉与文案都走**虚构**路线——标签也建议选泛化的 `Economy` 而非 `Cryptocurrency`。
4. 顺序即优先级。**把最能定义你游戏的那个放第一**。
5. 用 Tag Wizard 找"邻居"：看看推荐位里的游戏都挂了什么标签。

## 五、素材规格

| 素材 | 规格要点 |
|------|---------|
| 主胶囊图（Header Capsule） | 616×353，必须能被缩到 460×174 仍清晰 |
| 小胶囊图 | 462×174、231×87 |
| 库页面 hero | 3840×1240（超宽），中心留出被裁切后的安全区 |
| Logo | 透明底 PNG，宽度不超过胶囊图的一半 |
| 截图 | 至少 5 张，1920×1080 或更高，**无任何 UI 边框与平台水印** |
| 预告片 | 30–60 秒，前 3 秒必须有真实玩法画面 |
| 成就图标 | 64×64，游戏内显示为 32×32，设计时按 64 画 |

**截图文案规则**：每张截图左上角放一句话说明，字体要大到手机屏幕能读；不要在图上堆参数表。

**预告片规则**：用**真实游戏画面**，不要用概念图或过场动画；节奏要在 15 秒内展示核心循环；不要放片头 logo（会损失完播率）。

## 六、合规披露

Steam 的内容调查问卷与 AI 披露必须如实填写：

- **AI 生成内容**：若用了 AI 生成美术/文本/音频，需在问卷中披露。
- **第三方软件与 DRM**：如实列出。
- **游戏内购买**：有 IAP 就勾选，并确保商店页描述与游戏内一致。
- **成熟内容描述符**：按实际内容勾选，不要为了减少审核摩擦而漏报。
- **虚构题材声明**：Hashrise 用虚构币种（NCX / GGX / ₥），商店页要明确写"游戏内货币均为虚构，不涉及任何真实加密资产或金融产品"——这既是合规要求，也顺手关掉了一类玩家疑虑。
- **年龄分级**：涉及题材（矿场、电力、老矿主故事）按实际内容评估，post-MVP 还要按地区定价与分级分别处理。

## 七、多语言本地化

商店页文案是**转化漏斗的第一环**，本地化优先级应高于游戏内文本。

顺序建议：

1. **先定英文母版**，把短描述与 About 的英文敲定并通过评审。
2. **商店页的 6–10 种语言优先**（依据目标市场销量分布，不是按语种数量）。
3. 译文要**本地化**而非直译：短描述在德语/西语里普遍要更短，术语要统一（同一货币在所有语言里同名）。

Hashrise 的做法：商店页本地化与成就文案本地化一起做，术语表（货币名、矿机名、系统名）单独维护，避免各语言各叫各的。

## 八、发布前检查门

上架前逐项确认，任何一项不过就退回：

- [ ] 短描述一句话讲清玩法，无形容词堆砌
- [ ] About 四块齐全，bullet 全部动词开头且能被截图佐证
- [ ] 标签顺序合理，前 4 个是最能定义游戏的
- [ ] 全部素材尺寸符合规格，主胶囊图缩小后仍可读
- [ ] 至少 5 张截图，首屏截图能独立表达游戏类型
- [ ] 预告片前 3 秒是真实玩法画面
- [ ] 合规问卷已填，AI 内容已披露
- [ ] 虚构题材声明已写明
- [ ] 各语言术语一致，短描述未超长
- [ ] 商店页描述与游戏内实际玩法一致（承诺了做不到的事 = 差评来源）

## 九、上架后的第一周

商店页不是一次性工程，发布后要持续调：

- **盯评价**。差评里反复出现的点，要么改文案（如果本来就没承诺），要么改游戏。
- **看转化**。愿望单增长与商店页访问量的比值掉了，多半是主胶囊图或短描述的问题。
- **A/B 换主胶囊图**。同一个游戏换封面，转化差异可以到 30%。
- **发第一条更新公告**，把版本号与改动点写清楚。

## 常见坑

| 坑 | 后果 | 修法 |
|----|------|------|
| 短描述写成一堆形容词 | 玩家划走 | 第一句必须是具体玩法 |
| 标签照抄热门游戏 | 出现在错误的推荐位 | 先定类型标签再选机制标签 |
| 预告片用概念图 | 完播率极低 | 全用真实画面 |
| 承诺了游戏里没有的系统 | 上线即差评 | 每条 bullet 都要能被截图佐证 |
| 只做英文就上架 | 漏掉主要市场 | 先英文母版，再按销量分布排优先级 |
| 商店页写完就不动了 | 转化持续走低 | 发布后持续 A/B 与迭代 |
