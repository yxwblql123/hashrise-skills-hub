# 离线收益对账

放置游戏的核心留存钩子是**离线收益**：玩家关掉几小时回来，应该"挂机必有得"。但离线结算是最容易被刷、被投诉、被写崩的一块。

本技能给出 Hashrise 的 ADR-002 决策与实现纪律。

## 三个核心决策

### 1 · 时钟用 `OS.get_unix_time()`，不用计时器

```gdscript
# ✅ 权威墙钟：不受暂停、帧率、切后台影响
var away_sec: int = clamp(
    OS.get_unix_time() - saved.timestamp,
    0,
    HARD_CAP          # 24 小时
)
```

**为什么不用 Timer / 帧累计**：
- 切后台、暂停会**丢失**时间（玩家觉得被偷了时间）
- 掉帧或低帧率会让累加时间**膨胀**（多给收益）
- 都不符合"离开多久就结算多久"的直觉

**为什么不用服务端校时**：防作弊最彻底，但 MVP 没有后端。post-MVP 再加，客户端逻辑要预留替换点。

### 2 · 硬上限 24 小时，防改本地时钟

```gdscript
const HARD_CAP: int = 86400   # 24h
away_sec = clamp(now - saved.timestamp, 0, HARD_CAP)
```

玩家把手机时钟往前调，就能刷出海量收益。**必须**有硬上限。

注意：超长流失**按上限结算**，不丢失——玩家回来仍然拿到 24 小时的量，不会因为改了时钟而颗粒无收。

### 3 · 随机用种子化 RNG，且 seed 持久化

```gdscript
# 新档时随机生成 seed 并存进存档
saved.rng_seed = randi()
# 每次启动从存档续接
RNG.seed = saved.rng_seed
```

**为什么要持久化 seed**：如果每次启动都重新随机，那么：

- 在线行情游走会在每次启动时"跳变"，玩家会看到价格莫名跳一下
- 离线事件的抽样无法复现，出了 bug 无法回放、无法审计

**续接 seed 后**，同一存档的随机序列**跨会话连续**，可复现、可回放、可审计。

## 结算公式

```
away_sec   = clamp(now − saved.timestamp, 0, HARD_CAP)
base       = saved_net_rate × eff × min(away_sec, cap)      # 价格冻结
event_loss = RNG.sample_offline_events(away_sec)            # 种子化抽样
event_loss = min(event_loss, 0.4 × base)                    # 封顶 40%
return     = max(0, base − event_loss)                      # 永远非负
```

四个细节，每条都是一条红线：

| 细节 | 规则 | 理由 |
|------|------|------|
| 价格冻结 | 用**存档时**的行情价算 base | 避免"睡一觉血亏"，玩家看到的是离开时的世界 |
| 事件封顶 40% | `event_loss ≤ 0.4 × base` | 损失不能吃掉全部收益，玩家不会觉得被惩罚 |
| 结果非负 | `max(0, ...)` | 任何情况下离线收益不为负 |
| RNG 只管事件 | base 不依赖 RNG | 主体收益确定，只有事件损失带随机 |

**为什么 base 不依赖 RNG**：玩家对"我离开 8 小时，应该拿到约 X"要有可预期感。如果主体收益也随机，结算界面就没法给出准确的数字。

## 离线效率与上限档位

```
离线收益 = 存档净收益 × OFF_EFF × min(离线时长, 上限)
```

| 状态 | OFF_EFF | 时长上限 |
|------|---------|---------|
| 免费 | 0.50 | 8 小时 |
| 去广告订阅 | 0.625 | 12 小时 |
| **系统硬上限** | — | **24 小时（谁都突破不了）** |

订阅加成**必须**受硬上限约束，否则订阅玩家与免费玩家的离线收益会拉开到无法追赶，间接构成 P2W（见 `hashrise-monetization-guard`）。

## 切后台要存档

```gdscript
func _notification(what: int) -> void:
	if what == NOTIFICATION_WM_GOING_INTO_BACKGROUND:
		SaveManager.save()   # 时间戳贴近真实离开时刻
```

不这样做，玩家在应用切后台时被杀进程，回来时 `away_sec` 会算得比实际离开时间短——**玩家觉得收益被吃了**，这是最常见的差评来源之一。

## 事件抽样用 `away_sec` 缩放概率

```gdscript
func sample_offline_events(away_sec: int) -> float:
	var total := 0.0
	for ev in EVENTS:
		var p := clamp(ev.base_rate * away_sec / 3600.0, 0.0, ev.max_p)
		if RNG.randf() < p:
			total += ev.loss_rate * away_sec / 3600.0
	return total
```

关键：**概率随离线时长线性缩放**，且每类事件有 `max_p` 上限。这样：

- 离线越久，遇到事件的概率越高（符合直觉）
- 但不会因为离开太久而必定被事件打爆（`max_p` 兜底）

## 实现纪律

- [ ] 时间戳用 `OS.get_unix_time()`，不用 `Time.get_ticks_msec()`
- [ ] 有 24h 硬上限，且超限按上限结算
- [ ] seed 在新档生成并持久化，启动时续接
- [ ] base 用存档时的行情价，不重新计算
- [ ] 事件损失封顶 40% × base
- [ ] 结果 `max(0, ...)`
- [ ] 切后台触发存档
- [ ] 结算界面要**先显示预估数字**，再给"看广告翻倍"选项
- [ ] 有 `rng_seed` 的存档迁移路径（老档没这个字段要有默认值）

## 结算界面的 UX

玩家对离线收益的信任来自"数字说得通"。结算弹窗要显示：

```
离开时长    8 小时 12 分
基础收益    ×0.50（免费效率）      → 1,240 ₥
事件损失    过热 ×2                 → −180 ₥
─────────────────────────────
合计        1,060 ₥
```

- **分解到每一项**，不要只给总数。玩家看到"为什么少了 180"才不会愤怒。
- 先展示总额与分解，再给"看广告翻倍"选项（翻倍部分也要标注上限）。
- 时长被硬上限截断时，明确显示"（已按 24 小时上限计算）"。

## 常见坑

| 现象 | 根因 | 修法 |
|------|------|------|
| 改手机时间能刷收益 | 没有硬上限 | 加 24h clamp |
| 玩家说"回来收益变少" | 切后台没存档 | 监听 `NOTIFICATION_WM_GOING_INTO_BACKGROUND` |
| 每次启动价格莫名跳变 | seed 没持久化 | 存档存 `rng_seed`，启动续接 |
| 离线一夜血亏 | 离线时行情实时游走 | 用存档时的冻结价 |
| 事件损失吃掉全部收益 | 没有封顶 | `min(loss, 0.4 × base)` |
| 离线 3 小时和离线 8 小时收益一样 | 时长没进公式 | `min(away_sec, cap)` |
| headless 测试里结算结果随机 | 测试未固定 seed | 测试里显式设 seed |
