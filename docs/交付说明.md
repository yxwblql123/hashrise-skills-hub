## 二、双层目录设计（关键决策）

参考的 zgg 电商技能库只有第三方开源条目。这次做了**结构性升级**：

| | 第三方条目 | 第一方条目 |
|---|---|---|
| 来源 | 23 个公开仓库 | 本仓库自研 |
| `verification` | `source-checked` | `first-party` |
| `tested` | **一律 false** | **true** |
| 额外字段 | `license_note` | `evidence`（证据来源） |
| 徽章 | 「仅核实来源」 | 「已验证」 |

**为什么这么分**：zgg 那套把"来源已核对"和"业务已实测"混在一起，容易让用户误判。这里把两者在数据层、UI 层、文档层三处都显式区分开。

- 第三方条目全部标 `tested: false`——只核实了文件存在、commit 与内容 sha256，**没有做业务效果实测**
- 第一方 9 个技能的方法全部来自 Hashrise 项目内的真实文档与代码，`evidence` 字段写明出处

### 许可证如实登记

zgg 那套没这一层。这次做了：

| 许可证 | 条目 | 处理 |
|--------|------|------|
| MIT | 多数 | 正常使用 |
| Apache-2.0 | NVlabs/Skill2Env、nick-vas/hyperdot | 正常使用 |
| **BUSL-1.1** | RandallLiuXin/GodotMaker | `license_note` 提示有条件分发 |

前端对非 MIT/Apache 的条目用醒目徽章标出，`validate.mjs` 强制要求带 `license_note`。

## 四、目录是怎么做出来的（可复现）

**没有用 GitHub API 扫仓库**——配额只有 60 次/小时，扛不住 33 万个 SKILL.md。改用本地浅克隆，零 API 消耗：

```
候选仓库列表（25 个）
  → 本地浅克隆 --depth 1（--quiet）
  → 全量 SKILL.md frontmatter 抽取（112,822 条）
  → 路径关键词预筛（超大聚合仓库用）
  → 人工逐条阅读与策展（181 条）
  → 记录 commit + 内容 sha256
```

产物 `scripts/curate.py` 是**可重跑**的：加新条目只需在 `SELECTION` 里加一行，重新策展即可。

## 六、真实踩过的坑（都已修）

### 1 · Windows 换行符摧毁完整性校验

`catalog.json` 自带 sha256 校验，而 Windows 的 Git 默认 `core.autocrlf=true` 会把 LF 转成 CRLF——**12035 行各多 1 字节，哈希对不上，技能完全不可用，但页面照样能开**，极易误判"装好了"。

修复：
```bash
git config core.autocrlf false
git checkout HEAD -- data/catalog.json
```

并且**把这个坑写进了构建脚本**：检测到 CRLF 直接报错并打印修复命令。`validate.mjs` 与 `tests/catalog.test.mjs` 都有对应断言。

### 2 · 目录级 `rm` 被沙箱守卫拦下

构建脚本原本 `rm -rf dist`，撞上 WorkBuddy 的安全删除守卫（本地预览服务占用目录时必然失败）。改为**逐项覆盖写入**，效果等价且不会误删。

### 3 · `secrets` 上下文不能出现在 `if` 里

GitHub Actions 校验器直接拒绝 `if: ${{ secrets.X != '' }}`。解法是用 `config` job 在 `run` 步骤读 secrets、写成 job output，下游只判 output。这个坑已经写进 `hashrise-godot-ci-build` 技能。

### 4 · 第一方条目的 commit 死循环

第一方技能就在本仓库里，`source_commit` 指哪个 commit？指向自己会成环。

解法：**两段式提交**——先提交技能源码，把那次 commit 写进 `data/first-party-commit.txt`，再策展目录（目录引用该 commit），最后提交目录。这样目录里的 commit + sha256 可以被外部独立核实，且不构成循环。

## 九、诚实的边界

- **第三方 181 条全部 `tested: false`**。核实了文件真实存在、commit 与内容 sha256，**没有做业务效果实测**。安装后可能仍需调试。
- 部分第三方技能需要额外账号或付费 API（如 Steamworks MCP 需要配置 Steamworks 账号），装前先看详情页。
- 目录是**精选快照**，未覆盖全网。全网同名技能仓库有数千个。
- 检索是**关键词 + 别名匹配**，不是语义搜索。用户的自然语言需要先转成引擎与阶段短语。
- 第一方技能的方法**可迁移，但具体阈值与配置需按项目调整**——它们带着 Hashrise 的 Godot 4.2.2 / 2D 移动端 / GL Compatibility 背景。
